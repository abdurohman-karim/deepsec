# DeepSec

Личный «антивирус» для Windows, который охраняет сессии Telegram Desktop (`tdata`) от стилеров
и сообщает обо всём в Telegram-бота, через которого им же и управляют.

## Почему это важно

Стилеры (Lumma, RedLine, Vidar и десятки «граберов») просто копируют папку `tdata`. Этого достаточно,
чтобы открыть ваш аккаунт на другом компьютере — **облачный пароль (2FA) не спасает**, потому что
вор получает уже авторизованный сеанс, а не логинится заново.

## Как работает

```
Windows Security log ──EvtSubscribe──▶ Детектор ──▶ Реакция (kill, firewall, блокировка ПК)
   ▲ 4663 чтение tdata/ловушек                 │
   │ 4624/4625 входы, RDP                      └──▶ Бот aiogram ──▶ вам в Telegram
   │ 4719 аудит отключён, 1102 журнал очищен          ▲   кнопки и команды
SACL «аудит чтения» на tdata ─────────────────────────┘
```

1. **Аудит чтения файлов.** Setup включает в Windows аудит файловой системы и вешает SACL «Чтение данных»
   на `key_datas` и файлы аккаунтов в `tdata`. Теперь при каждом чтении Windows пишет событие 4663
   с путём exe и PID — его агент получает в реальном времени.
2. **Белый список по подписи.** Читать tdata можно только `Telegram.exe` с валидной подписью Telegram FZ-LLC
   (и Защитнику Windows). Вирус, переименованный в `Telegram.exe`, подпись не подделает.
3. **Ловушки.** В `%APPDATA%` создаются фейковые `tdata` от AyuGram / Kotatogram / 64Gram — их ищут стилеры.
   Любое чтение ловушки — 100% чужой.
4. **Реакция за миллисекунды:** процесс и его дети убиваются, exe получает запрет сети в брандмауэре
   (чтобы не успел отправить архив, даже если его перезапустят), можно сразу заблокировать ПК.
5. **«Кто-то подключился»:** RDP-входы, входы и разблокировки Windows, подбор пароля, запуск AnyDesk /
   TeamViewer / RustDesk / RMS и др.
6. **Защита самой защиты:** самопроверка (агент сам читает canary-файл и ждёт событие), тревога при отключении
   аудита или очистке журнала, команды, ослабляющие защиту, — только с TOTP-кодом с телефона.

## Ограничения (честно)

- Это обнаружение и реакция, а не запрет: Windows сообщает о чтении **после** открытия файла. `key_datas`
  маленький — стилер успеет его прочитать. Шанс есть на то, чтобы убить процесс до отправки архива,
  и на то, что вы сразу узнаете и завершите сеансы. Настоящий запрет чтения требует драйвера-минифильтра ядра.
- Если вирус внедрится в сам `Telegram.exe` или получит права администратора — он может обойти защиту
  (но отключение аудита/очистка журнала вызовут тревогу).
- Если украдут сессию Telegram, вор увидит уведомления бота и сможет нажимать кнопки, не требующие кода.
  Опасные команды он без TOTP выполнить не сможет.

## Установка

Нужны Windows 10/11, Python 3.11+ и Telegram Desktop с telegram.org (версия из Microsoft Store пока не поддерживается).

1. Создайте бота у [@BotFather](https://t.me/BotFather), узнайте свой ID у [@userinfobot](https://t.me/userinfobot).
2. Положите проект и venv туда, куда без прав администратора писать нельзя — агент работает от SYSTEM,
   и код в папке пользователя вирус мог бы подменить:
   ```powershell
   # PowerShell от имени администратора
   git clone <repo> "C:\Program Files\DeepSec"
   cd "C:\Program Files\DeepSec"
   py -3.12 -m venv .venv
   .venv\Scripts\pip install -r requirements.txt
   ```
3. Запустите Telegram Desktop и выполните setup (от администратора):
   ```powershell
   .venv\Scripts\python -m deepsec setup
   ```
   Он найдёт `tdata`, проверит подпись вашего `Telegram.exe`, создаст ловушки, включит аудит, спросит токен
   бота и покажет TOTP-секрет — добавьте его в аутентификатор **на телефоне**. Затем зарегистрирует задачу
   планировщика «DeepSec Agent» (SYSTEM, при старте Windows) и запустит её.
4. В боте: `/status`, затем `/selftest` — должно быть «✅ Аудит работает».

Диагностика: `python -m deepsec check`. Лог: `C:\ProgramData\DeepSec\agent.log`.

### Проверка «боевой» реакции

Изобразите стилер копией безобидной утилиты — агент убьёт её и запретит ей сеть (саму `powershell.exe` или
`python.exe` для теста не используйте: им тоже запретят сеть):

```powershell
copy C:\Windows\System32\certutil.exe $env:TEMP\stealer-test.exe
& $env:TEMP\stealer-test.exe -hashfile "$env:APPDATA\AyuGram Desktop\tdata\key_datas"
```

В бот придёт тревога «Кто-то читает файлы-ловушку tdata». Потом: `/blocked` и `/unblock all КОД`.

## Команды бота

| Команда | Что делает |
|---|---|
| `/status`, `/events`, `/selftest` | состояние, последние инциденты, проверка аудита |
| `/lock` | заблокировать экран и выкинуть RDP-сеансы |
| `/isolate` | отрезать ПК от сети (агент остаётся на связи) |
| `/kill PID`, `/blocked`, `/arm` | завершить процесс, список блокировок, включить авто-реакцию |
| `/disarm КОД` | только уведомления |
| `/unisolate КОД`, `/unblock ПРАВИЛО\|all КОД` | вернуть сеть / снять блокировку |
| `/trust ID КОД` | доверять exe из инцидента (по SHA-256) — для бэкапа и т. п. |

## Что ещё обязательно сделать (без этого защита неполная)

1. **Локальный код-пароль в Telegram Desktop** (Настройки → Конфиденциальность → Код-пароль). Он шифрует
   `tdata` — украденная копия без него бесполезна. Это самая сильная мера из всех; пароль — длинный.
2. **Облачный пароль (2FA)** — защищает от входа по SMS-коду.
3. **Автозавершение неактивных сеансов** — Настройки → Устройства → «Если сеанс неактивен» → 1 неделя.
4. Не запускайте кряки, «читы», «бесплатный софт» — основной путь заражения стилерами.
5. При тревоге — с телефона: Настройки → Устройства → **«Завершить все другие сеансы»**.

## Разработка

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt pytest
.venv/bin/pytest
```

Логика (разбор событий, правила, доверие, TOTP, бот) тестируется на любой ОС; Windows-специфичное
(`monitors/eventlog.py`, `response.py`, `winacl.py`, `setup_win.py`) — только на Windows.
